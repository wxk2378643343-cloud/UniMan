# 高校后勤服务管理系统需求设计

## 1. 项目概述

高校后勤服务管理系统面向高校日常后勤事务，提供报修、投诉建议、公告通知、用户与角色管理、基础数据维护等功能。系统目标是把分散的线下后勤流程集中到统一平台中，提升普通用户、后勤人员与系统管理员之间的信息流转效率。

本系统只聚焦后勤业务管理，不在页面中展示安全研究、漏洞说明、防护配置等内容，也不单独设计安全相关角色。

## 2. 建设目标

1. 建立统一的后勤服务入口，方便师生提交维修、投诉和建议。
2. 支持后勤人员接收、处理、反馈服务工单。
3. 支持系统管理员查看服务数据、分配处理人员、发布公告。
4. 实现后勤事务从提交、受理、处理、完成、评价的闭环管理。
5. 提供清晰的后台管理页面，便于维护用户、角色、公告和业务数据。

## 3. 用户角色

### 3.1 普通用户

普通用户是后勤服务的主要申请人，包括学生、教职工等校内人员。普通用户可以登录系统、提交报修申请、查看处理进度、提交投诉建议、查看公告通知，并对已完成的服务进行评价。

### 3.2 后勤人员

后勤人员负责处理分配给自己的维修或服务工单。可以查看待处理任务、更新处理状态、填写处理结果、上传处理说明，并完成工单流转。

### 3.3 系统管理员

系统管理员负责系统日常业务管理，包括用户管理、角色管理、工单分派、公告管理、投诉处理跟踪、数据统计和基础信息维护。

## 4. 功能需求

### 4.1 登录与个人中心

系统应提供统一登录入口。用户登录后，根据角色进入对应页面。个人中心用于展示和维护个人基础信息。

功能包括：

1. 用户登录、退出登录。
2. 查看个人信息，包括姓名、账号、角色、联系方式、所属院系或部门。
3. 修改个人联系方式。
4. 修改登录密码。
5. 查看本人提交的报修、投诉和评价记录。

### 4.2 首页看板

首页用于展示当前用户最关心的业务信息。

普通用户首页显示：

1. 我的待处理报修数量。
2. 我的已完成报修数量。
3. 我的投诉建议处理状态。
4. 最新公告通知。

后勤人员首页显示：

1. 待接单工单数量。
2. 处理中工单数量。
3. 今日完成工单数量。
4. 近期分配任务列表。

系统管理员首页显示：

1. 报修总量、待处理量、处理中数量、已完成数量。
2. 投诉建议总量和待回复数量。
3. 公告发布数量。
4. 按类型、区域、状态统计的后勤服务数据。

### 4.3 报修管理

报修管理是系统核心业务模块，用于处理校园设施维修、宿舍维修、教学楼维修、办公区域维修等事项。

报修提交功能包括：

1. 选择报修类型，例如水电维修、门窗维修、网络设备、空调设备、公共设施、其他。
2. 填写报修地点，例如校区、楼栋、楼层、房间号。
3. 填写问题描述。
4. 上传现场图片。
5. 提交后生成报修单号。

报修处理流程包括：

1. 用户提交报修。
2. 系统管理员查看报修单并分派后勤人员。
3. 后勤人员接单并更新为处理中。
4. 后勤人员填写处理结果并标记完成。
5. 提交人确认完成并进行评价。

报修状态包括：

1. 待受理。
2. 已分派。
3. 处理中。
4. 待确认。
5. 已完成。
6. 已取消。

系统管理员报修管理功能包括：

1. 查看全部报修列表。
2. 按状态、类型、地点、提交人、时间筛选。
3. 查看报修详情。
4. 分派处理人员。
5. 修改工单状态。
6. 查看处理记录和评价结果。

### 4.4 投诉建议管理

投诉建议模块用于收集师生对食堂、宿舍、物业、维修、校园环境等后勤服务的意见。

用户端功能包括：

1. 提交投诉或建议。
2. 选择类型，例如食堂服务、宿舍管理、维修服务、校园环境、物业服务、其他。
3. 填写标题和详细内容。
4. 上传图片附件。
5. 查看处理状态和回复内容。

系统管理员端功能包括：

1. 查看投诉建议列表。
2. 按类型、状态、提交时间筛选。
3. 查看详情。
4. 填写处理回复。
5. 标记为已处理。
6. 对典型问题进行归类统计。

投诉建议状态包括：

1. 待处理。
2. 处理中。
3. 已回复。
4. 已关闭。

### 4.5 公告通知管理

公告通知模块用于发布后勤服务相关通知，例如停水停电通知、维修安排、食堂营业调整、宿舍检查通知等。

用户端功能包括：

1. 查看公告列表。
2. 查看公告详情。
3. 按发布时间浏览最新公告。

系统管理员端功能包括：

1. 新增公告。
2. 编辑公告。
3. 发布或下线公告。
4. 删除公告。
5. 设置公告标题、内容、发布时间、状态和发布范围。

公告状态包括：

1. 草稿。
2. 已发布。
3. 已下线。

### 4.6 用户管理

用户管理由系统管理员使用，用于维护系统账号。

功能包括：

1. 新增用户。
2. 编辑用户基础信息。
3. 重置用户密码。
4. 启用或禁用用户账号。
5. 按姓名、账号、角色、院系或部门查询用户。
6. 查看用户提交的业务记录。

用户信息字段包括：

1. 用户编号。
2. 登录账号。
3. 姓名。
4. 用户角色。
5. 手机号。
6. 邮箱。
7. 院系或部门。
8. 账号状态。
9. 创建时间。

### 4.7 角色管理

角色管理用于维护普通业务角色和页面菜单权限。

默认角色包括：

1. 普通用户。
2. 后勤人员。
3. 系统管理员。

功能包括：

1. 查看角色列表。
2. 新增角色。
3. 编辑角色名称和说明。
4. 配置角色可访问的业务菜单。
5. 启用或禁用角色。

### 4.8 基础数据管理

基础数据用于支撑报修、投诉和统计分析。

管理内容包括：

1. 校区信息。
2. 楼栋信息。
3. 楼层和房间信息。
4. 报修类型。
5. 投诉建议类型。
6. 后勤服务部门。

基础数据功能包括：

1. 新增、编辑、删除基础数据。
2. 启用或禁用基础数据。
3. 按名称或状态查询。

### 4.9 服务评价

服务评价用于收集报修处理结果反馈。

功能包括：

1. 用户对已完成报修进行评分。
2. 用户填写评价内容。
3. 系统管理员查看评价结果。
4. 后勤人员查看本人服务评价。
5. 系统按人员、类型、时间统计满意度。

评价字段包括：

1. 评分。
2. 评价内容。
3. 评价人。
4. 评价时间。
5. 关联报修单。

### 4.10 数据统计

数据统计用于帮助系统管理员了解后勤服务运行情况。

统计内容包括：

1. 报修工单数量统计。
2. 报修类型分布。
3. 报修地点分布。
4. 工单状态分布。
5. 投诉建议类型分布。
6. 后勤人员处理数量统计。
7. 服务满意度统计。

统计页面应支持按时间范围筛选，例如今日、本周、本月、本学期和自定义时间。

## 7. 业务流程

### 7.1 报修流程

1. 用户登录系统。
2. 用户填写报修信息并提交。
3. 系统生成报修单。
4. 系统管理员查看并分派给后勤人员。
5. 后勤人员处理工单。
6. 后勤人员提交处理结果。
7. 用户确认完成并评价。
8. 工单归档。

### 7.2 投诉建议流程

1. 用户提交投诉或建议。
2. 系统管理员查看详情。
3. 系统管理员根据情况填写处理回复。
4. 用户查看回复。
5. 记录关闭。

### 7.3 公告发布流程

1. 系统管理员创建公告草稿。
2. 系统管理员编辑公告内容。
3. 系统管理员发布公告。
4. 用户在公告列表中查看。
5. 系统管理员可根据需要下线公告。

## 8. 非功能需求

### 8.1 易用性

1. 页面布局清晰，主要操作入口明显。
2. 表单字段应提供必要提示。
3. 列表页应支持搜索、筛选和分页。
4. 状态变化应有明确提示。

### 8.2 性能

1. 普通列表查询响应时间应控制在合理范围内。
2. 首页统计数据应避免长时间加载。
3. 图片附件应限制大小，避免影响系统访问速度。

### 8.3 兼容性

1. 支持主流桌面浏览器。
2. 页面布局应适配常见笔记本和台式机分辨率。
3. 关键功能在移动端浏览器中应可正常使用。

### 8.4 可维护性

1. 前后端模块划分清晰。
2. 业务状态和类型应统一维护。
3. 接口返回格式保持一致。
4. 重要业务操作应记录操作时间和操作人。

## 10. 验收标准

1. 用户能够正常登录并进入对应页面。
2. 普通用户能够完成报修提交、进度查看、投诉建议提交和公告查看。
3. 后勤人员能够查看分配工单并提交处理结果。
4. 系统管理员能够管理报修、投诉建议、公告、用户、角色和基础数据。
5. 报修流程能够完整流转到评价归档。
6. 投诉建议能够完成提交、回复和关闭。
7. 首页和统计页面能够展示核心业务数据。
8. 页面不出现安全研究、漏洞说明、防护配置等与后勤业务无关的内容。
