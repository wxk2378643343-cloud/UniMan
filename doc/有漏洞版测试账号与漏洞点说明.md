## 3. 当前保留的漏洞点

## 3.1 登录接口存在 SQL 注入风险

### 说明
登录接口在查询用户时，直接将前端传入的用户名和密码拼接到 SQL 语句中，没有采用参数绑定。

### 位置
接口：

```text
POST /api/auth/login
```

代码位置：
[main.py](G:\project\UniMan\with-vuln\backend\app\main.py)

### 风险
- 存在 SQL 注入风险
- 可能绕过登录校验
- 不符合安全开发规范

## 3.2 用户密码明文存储

### 说明
用户表中的密码以明文形式保存，没有进行哈希加密处理。

### 位置
表：`users`

接口：

```text
GET /api/users
```

### 风险
- 数据库泄露时会直接暴露用户密码
- 不符合真实系统安全要求

## 3.3 用户列表接口暴露敏感信息

### 说明
用户列表接口直接返回了密码字段。

### 位置
接口：

```text
GET /api/users
```

### 风险
- 敏感信息泄露
- 普通前端调用即可看到密码

## 3.4 缺少统一身份鉴权

### 说明
虽然前端保存了登录后的 token，但后端多数接口没有进行统一鉴权校验。

### 涉及接口示例

```text
GET /api/users
GET /api/roles
GET /api/repairs
GET /api/complaints
GET /api/notices
```

### 风险
- 未登录或低权限用户可直接访问后台数据
- 不能体现真实 RBAC 权限隔离

## 3.5 存在越权访问风险

### 说明
不同角色之间没有严格限制访问范围，学生、工作人员、管理员均可看到较完整的后台数据。

### 风险
- 普通用户可以访问不属于自己的信息
- 后台接口缺少按角色控制

## 3.6 文件上传缺少严格校验

### 说明
当前图片上传接口可以正常上传文件，但没有对类型、大小、扩展名进行严格限制。

### 位置
接口：

```text
POST /api/upload
```

### 风险
- 上传不安全文件的风险较高
- 缺少生产环境所需的白名单策略

## 3.7 CORS 策略过于宽松

### 说明
后端允许任意来源访问接口。

### 位置
后端跨域配置：

```python
allow_origins=["*"]
```

### 风险
- 任意来源前端脚本都可能直接调用接口
- 不利于生产环境安全控制

## 3.8 个人信息修改缺少严格校验

### 说明
右上角账户区域的“编辑个人信息”功能可以直接调用用户更新接口，没有做更严格的身份确认机制。

### 风险
- 当前实现偏演示用途
- 不能满足真实系统中的敏感操作要求

## 5. 测试建议

建议你优先做以下验证：

1. 使用不同角色账号登录系统，查看是否都能访问后台模块。
2. 直接访问用户列表接口，确认是否能看到明文密码。
3. 使用上传接口测试图片上传功能是否可正常返回文件地址。
4. 使用不同账号查看工单、公告、投诉、角色、用户数据是否存在越权展示。
5. 在论文中记录“有漏洞版”与后续“无漏洞版”的差异。

## 6. 说明

当前 `with-vuln` 版本用于教学演示、论文研究和对比测试，不适合直接部署到真实生产环境。后续如需实现安全修复版，应在 `without-vuln` 目录中重新进行鉴权、权限控制、密码加密、输入校验、上传校验和日志审计强化。
