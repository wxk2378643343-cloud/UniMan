# 高校后勤服务管理系统的漏洞研究与防护需求分析说明书

## 1. 项目概述

### 1.1 项目名称
基于高校后勤服务管理系统的漏洞研究与防护平台

### 1.2 项目背景
随着高校信息化建设不断推进，后勤服务逐步由线下登记、电话报修、人工派单转向线上统一管理。传统后勤管理方式存在信息分散、响应不及时、数据统计困难、责任追踪不清晰等问题。构建高校后勤服务管理系统可以提升报修、投诉、公告发布、资产维护等业务的处理效率。

同时，后勤服务管理系统涉及用户身份认证、业务数据流转、文件上传、权限分配、日志记录等多个 Web 应用关键环节。如果系统缺乏完善的安全设计，容易出现越权访问、注入攻击、跨站脚本、恶意上传、敏感信息泄露等问题。因此，本项目不仅要实现后勤业务管理功能，还要围绕系统漏洞研究与安全防护进行设计，形成业务管理与安全防护一体化的平台。

### 1.3 项目目标
本项目拟基于 `FastAPI` 构建后端服务，基于 `Vue` 构建前端管理页面，设计并实现一个适用于高校后勤场景的服务管理系统。在实现基础业务功能的同时，对常见 Web 安全漏洞进行研究、复现和防护验证，提升系统的安全性、可维护性和可审计性。

### 1.4 技术路线
- 后端：Python、FastAPI
- 前端：Vue
- 数据库：MySQL
- 鉴权方式：JWT
- 权限模型：RBAC
- 部署方式：前后端分离

## 2. 建设范围

### 2.1 业务范围
系统面向高校后勤服务场景，主要覆盖以下业务：
- 用户登录与权限管理
- 报修工单管理
- 投诉与建议管理
- 公告通知管理
- 楼宇与宿舍基础信息管理
- 资产与设备维护管理
- 数据统计分析

### 2.2 安全研究范围
系统重点研究并防护以下常见漏洞或安全风险：
- 身份认证薄弱带来的暴力破解风险
- 权限控制不严带来的越权访问风险
- 输入校验不足带来的 SQL 注入风险
- 富文本或文本输入导致的 XSS 风险
- 文件上传校验不足导致的恶意文件上传风险
- 敏感操作缺乏审计导致的安全追踪困难
- 接口暴露、跨域配置不当引发的 API 安全风险

## 3. 用户角色分析

### 3.1 学生
学生是系统的普通使用者，主要使用系统进行后勤服务申请和进度查看。

主要权限如下：
- 注册与登录系统
- 提交报修工单
- 提交投诉与建议
- 查看公告通知
- 查看本人提交记录及处理进度
- 对服务结果进行评价

### 3.2 后勤工作人员
后勤工作人员负责处理具体业务任务。

主要权限如下：
- 查看分配给自己的工单
- 更新工单处理状态
- 填写处理结果
- 上传处理图片或说明
- 查看个人工作记录

### 3.3 部门管理员
部门管理员负责各业务条线的管理和任务分配。

主要权限如下：
- 查看本部门工单与投诉信息
- 分配任务给后勤工作人员
- 管理楼宇、宿舍、设备等基础信息
- 审核和发布部门相关信息
- 查看部门统计报表

### 3.4 系统管理员
系统管理员负责整个平台的系统配置与权限管理。

主要权限如下：
- 用户管理
- 角色管理
- 权限管理
- 菜单管理
- 系统参数配置
- 公告统一管理
- 查看系统日志与安全日志

### 3.5 安全审计员
安全审计员负责查看安全事件和审计数据。

主要权限如下：
- 查看登录日志
- 查看操作日志
- 查看异常请求记录
- 查看漏洞防护状态
- 查看安全审计报表

## 4. 功能需求分析

### 4.1 用户与权限管理模块

#### 4.1.1 功能说明
该模块负责实现系统用户身份认证、角色分配和权限控制，是整个平台的基础模块。

#### 4.1.2 主要功能
- 用户注册与登录
- 密码修改与个人信息维护
- 用户列表管理
- 角色创建与分配
- 权限点管理
- 基于角色的访问控制
- JWT 登录态校验

#### 4.1.3 业务要求
- 用户密码必须加密存储
- 登录接口需要具备失败次数记录能力
- 不同角色访问的菜单和接口必须隔离
- 普通用户只能访问本人数据

### 4.2 报修工单管理模块

#### 4.2.1 功能说明
该模块用于实现学生报修、管理员派单、工作人员处理、用户评价的完整业务闭环。

#### 4.2.2 主要功能
- 提交报修申请
- 上传故障图片
- 按故障类型分类
- 工单分配
- 工单状态流转
- 处理记录填写
- 用户评价与反馈

#### 4.2.3 状态设计
建议工单状态包括：
- 待受理
- 已分配
- 处理中
- 已完成
- 已评价
- 已关闭

### 4.3 投诉与建议管理模块

#### 4.3.1 功能说明
该模块用于收集学生对后勤服务的投诉、建议和意见，并支持分类处理和结果反馈。

#### 4.3.2 主要功能
- 提交投诉
- 提交建议
- 分类查看记录
- 管理员处理与回复
- 状态跟踪

### 4.4 公告通知管理模块

#### 4.4.1 功能说明
该模块用于统一发布后勤相关公告，包括停水停电、维修通知、节假日安排等。

#### 4.4.2 主要功能
- 公告新增
- 公告编辑
- 公告发布与下线
- 公告分类管理
- 公告查看统计

### 4.5 楼宇与宿舍管理模块

#### 4.5.1 功能说明
该模块用于维护学校楼宇、宿舍、房间等基础信息，为报修与设备管理提供定位依据。

#### 4.5.2 主要功能
- 楼宇信息管理
- 宿舍信息管理
- 房间信息管理
- 位置关联报修
- 区域筛选与查询

### 4.6 资产与设备管理模块

#### 4.6.1 功能说明
该模块用于对公共设施和后勤设备进行统一登记、巡检与维护记录管理。

#### 4.6.2 主要功能
- 设备信息录入
- 设备分类管理
- 维护记录管理
- 故障登记
- 维修历史查询

### 4.7 数据统计与可视化模块

#### 4.7.1 功能说明
该模块用于统计后勤业务运行情况，为管理人员提供决策依据。

#### 4.7.2 主要功能
- 工单总量统计
- 工单完成率统计
- 部门处理效率统计
- 故障类型分布统计
- 投诉数量趋势分析
- 设备故障频率分析

## 5. 安全需求分析

### 5.1 身份认证安全
- 登录密码必须采用不可逆加密存储
- 登录接口应限制连续失败次数
- 用户登录后必须使用 Token 进行身份校验
- Token 应设置有效期并支持失效控制

### 5.2 权限控制安全
- 系统应采用 RBAC 模型实现细粒度权限控制
- 不同角色必须限制访问不同菜单和接口
- 普通用户只能查看和操作自己的数据
- 后台管理接口必须进行权限校验，防止越权访问

### 5.3 输入校验与注入防护
- 所有输入字段应进行长度、类型和格式校验
- 数据库操作必须使用安全参数绑定方式
- 禁止直接拼接 SQL 语句处理用户输入
- 对特殊参数和危险字符进行过滤或拒绝

### 5.4 XSS 防护
- 对用户输入的文本内容进行转义处理
- 对公告内容、投诉内容等展示字段进行安全过滤
- 禁止前端直接渲染未经处理的危险 HTML

### 5.5 文件上传安全
- 限制上传文件大小
- 限制上传文件类型和后缀
- 上传文件应重命名存储
- 上传目录不得直接执行脚本
- 应记录上传者、上传时间和关联业务信息

### 5.6 日志审计安全
- 记录登录成功与失败日志
- 记录用户敏感操作日志
- 记录权限变更日志
- 记录异常访问和可疑请求
- 支持按时间、用户、类型查询日志

### 5.7 接口安全
- 前后端分离场景下应合理配置 CORS
- 敏感接口必须要求身份认证
- 关键数据接口应进行权限和参数双重校验
- 返回信息应避免泄露系统内部实现细节

## 6. 页面需求分析

### 6.1 登录页
页面应包含：
- 用户名输入框
- 密码输入框
- 登录按钮
- 角色提示信息
- 验证码预留区域

设计要求：
- 页面简洁清晰
- 突出系统名称与主题
- 支持错误提示反馈

### 6.2 学生端首页
页面应展示：
- 公告通知
- 我的报修
- 我的投诉
- 快捷申请入口
- 服务进度概览

设计要求：
- 以信息查询和快捷操作为主
- 布局简洁，便于快速提交业务

### 6.3 报修提交页
页面应包含：
- 报修类型选择
- 故障地点选择
- 故障描述输入
- 图片上传
- 联系方式
- 提交按钮

设计要求：
- 表单结构清晰
- 支持必填校验
- 支持图片预览

### 6.4 工单管理页

- 状态标签
- 工单详情弹窗或详情页

设计要求：
- 适合后台高频操作

### 6.5 公告管理页

- 公告列表

- 用户列表
- 角色列表

### 6.7 统计分析页
页面应包含：
- 统计卡片
- 柱状图
- 折线图

- 登录日志列表
- 操作日志列表

## 7. 非功能需求

### 7.1 性能需求
- 系统应满足一般校园后勤场景下的并发访问需求
- 常规查询接口应具备较快响应速度
- 统计页面应支持基础数据汇总与分页展示

### 7.2 可用性需求
- 页面布局应清晰易用
- 关键业务流程应步骤明确
- 错误提示应清楚直观
- 常用功能应减少操作层级

### 7.3 可维护性需求
- 后端接口命名规范统一
- 前后端模块划分清晰
- 日志、配置、权限等公共模块应独立设计
- 代码结构应便于后期扩展

### 7.4 安全性需求
- 敏感数据不得明文存储
- 权限控制必须覆盖前端和后端
- 关键操作必须可追踪
- 系统应具备基础异常监测能力

## 9. 预期成果

本项目完成后，应形成以下成果：
- 一个可运行的高校后勤服务管理系统
- 一套清晰的角色权限控制机制
- 一组面向常见 Web 漏洞的防护设计方案
- 一套安全日志与审计机制
- 一份可用于课程设计、毕业设计或论文撰写的系统文档基础材料

## 10. 总结
本系统以高校后勤服务场景为基础，以漏洞研究与防护为特色，在满足实际业务管理需求的同时，强化系统安全设计。项目既具备实际应用价值，也具备较强的教学研究意义。后续设计与开发阶段可在本需求文档基础上继续细化系统架构、数据库设计、接口设计、页面原型和测试方案。
